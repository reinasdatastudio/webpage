Rにおけるデータクリーニングのプロセス（チェックリスト）

Data Cleaning
Rでのデータクリーニングをステップごとに解説したチェックリスト。欠損値処理、データ型の修正、データ整形など、分析前に確認すべきポイントを分かりやすくまとめています。
Published

April 6, 2026

データクリーニングは、データ分析において最も重要なステップの一つです。

しかし実際には、

  • 欠損値の確認を忘れてしまう
  • データ型が正しくないまま進めてしまう
  • データ構造が整っていない

といったことがよく起こります。

この記事では、Rでデータを扱う際に役立つデータクリーニングのチェックリストを紹介します。

ちゃんとクリーニングのプロセスが出来ているか確認するために、このページをブックマークするのもおすすめです。

0. データとパッケージの読み込み

データの読み込みはもちろん、必要なパッケージも忘れず読み込みます。

library(tidyverse)
df <- read_csv("your_data.csv")

1. まずはデータを理解する

クリーニングを始める前に、必ずデータの中身を確認します。

glimpse(df)
summary(df)

確認するポイント：

  • どんな変数があるか
  • データ型は適切か
  • 明らかにおかしい値はないか

自分が取り扱うデータをちゃんと理解する事は、一番と言っていいほど大事だと思っています。

2. 列名を整える

列名がバラバラだと後々扱いづらくなります。

names(df)

よくある修正：

  • スペースを削除
  • 小文字に統一
  • 命名ルールを揃える
df <- df %>% rename(Age = age, Income = income)

💡 janitor::clean_names()を使うと一括ですべて小文字に整えられます。

3. 欠損値の処理

欠損値（NA）は必ず確認します。

自分も使っている、欠損値を確認するためのコードをいくつか紹介します。

Code Meaning 
colSums(is.na(df))
 各列ごとの欠損値（NA）の数をカウント 
rowSums(is.na(df))
 各行ごとの欠損値（NA）の数をカウント 
sum(is.na(df))
 データフレーム全体に含まれる欠損値（NA）の総数 
df[!complete.cases(df), ]
 欠損値を含むすべての行を表示（列名に関係なく

dplyr

df %>% filter(is.na(column_name))
 指定した列に欠損値（NA）が含まれている行を抽出

対応方法：

  • 行ごと削除
  • 値を補完
  • そのまま残す（理由を理解した上で）
df <- df %>% drop_na()
#または
df <- df %>% mutate(income = replace_na(income, 0))

4. データ型の修正

データ型が間違っているとエラーや誤った分析につながります。

str(df)

は、データの大きさ、列名、データ型などを表示します。

修正例：

df <- df %>% mutate(age = as.numeric(age),
                    date = as.Date(date),
                    category = as.factor(category))

5. データの整形（構造を整える）

データが「tidy」な形になっているか確認します。

df <- df %>% pivot_longer(
  cols = c(math, english),
  names_to = "subject",
  values_to = "score")

このコードは、

「math と english の列を、subject という新しい列の値に変換し、それぞれのスコアを score という別の列にまとめる」

という意味です。

つまり、データは次のように変換されます：

変換前：

name math english
A 80 90
B 70 85

変換後：

name subject score
A math 80
A english 90
B math 70
B english 85

このようにデータを整えることで、

  • group_by(subject) で集計しやすくなる
  • グラフの作成が簡単になる

といったメリットがあります。

6. 文字列のクリーニング

文字データには表記ゆれがよくあります。

df <- df %>% mutate(country = str_trim(country),
                    country = str_to_lower(country))

7. 重複データの削除

重複データがあると分析結果に影響します。

df <- df %>% distinct()

特定の列だけの重複を削除する場合：

df <- df %>% distinct(id, .keep_all = TRUE)

8. 外れ値の確認

異常な値がないか確認します。

summary(df$income)

# 並べかえると見やすい
# 下から上の値
df %>% arrange(income)

# 上から下の値
df %>% arrange(desc(income))

または可視化：

ggplot(df, aes(y = income)) +
  geom_boxplot()

箱ひげ図では、外れ値が点として表示されます。

外れ値を削除するか残すかはデータによりますが、自分は明らかな入力ミスでない限りはとりあえず残すことが多いです。
その上で、分析への影響を見ながら改めて判断します。
「この外れ値は、分析結果を大きく歪めてでも重要なのか？」

9. データの妥当性チェック

最後に、データが論理的に正しいか確認します。

現実的にありえない値がないか確認。

例：

df %>%  filter(age < 0)

10. クリーンデータの保存

最後に、クリーンなデータを保存します。

write_csv(df, "cleaned_data.csv")

典型的なワークフロー

df %>% 
  clean_names() %>%  
  drop_na() %>% 
  mutate(...) %>% 
  pivot_longer(...)

慣れてきたらこのようにまとめて書くことができます。

ちなみに自分は、自分も人も見やすいように書くのが好きなので、毎回分けて書いています。

よくあるミス

  • データの理解をせずに始める
  • 途中で確認せずに進める
  • データ型を無視する
    • よくある例えは、factorがcharacterのままになっているなど
  • 整形されていないデータをそのまま使う

まとめ

データクリーニングは単なる作業ではなく、プロセスです。

チェックリストを使うことで：

  • ミスを防ぐ
  • 再現性のある分析ができる
  • 分析の質が向上する

新しいデータを扱うたびに、このチェックリストを見返してみてください。

実務でも、分析の問題の多くはデータが適切に整理されていないことが原因です。

こうしたプロセスを意識するだけでも、結果の信頼性は大きく変わります。
